# Раскрытие дерева каталога

## Реализация

- `ItemsPage` хранит отдельный набор полных путей для каждого корня.
  Мемоизированный `ItemsPageTree` получает стабильные обработчики и скалярные
  состояния контролов; раскрытие соседнего дерева не меняет его props.
  Фильтрация поиском не сбрасывает пути, завершение удаления освобождает их.
- `useRootItemDrag` измеряет список после прохождения порога движения 5 px.
  Обычное нажатие и отпускание не читают геометрию списка.
- `ItemName` повторяет измерение при изменении отображаемых строк и доступной
  ширины. Смена ссылки на предмет и изменение только высоты не пересоздают
  наблюдатель и не измеряют текст заново. `ItemTree` сохраняет объект предмета,
  если эффективный рецепт совпадает с ручным.
- Первичные подгонки названий группируются после layout-эффектов в микрозадачу:
  все сбросы ширины, затем все чтения геометрии, затем все записи. Это убирает
  чередование записи и чтения для каждого нового реагента. Повторное первичное
  уведомление `ResizeObserver` пропускается, ожидающие подгонки удаляются при
  размонтировании.
- `content-visibility: auto` позволяет браузеру пропускать работу с корнями вне
  экрана. Все корни остаются в DOM. Наведение/фокус снимают containment для
  подсказок и теней; анимации появления/удаления выполняются с полной отрисовкой.
  Перед чтением геометрии переноса включается раскладка всех реальных высот.

Виртуализации нет. Анимации высоты/прозрачности 150 мс, сокращённое движение,
последние данные удаляемых строк и статическая архитектура сохранены.

## Воспроизведение измерений

На работающем сервере `http://localhost:5174/`:

```shell
node scripts/measure-tree-builds.mjs e9aae5c41dc9fce825f0e7858c345b92508a97fa
```

Скрипт собирает два production-пакета с текущими одинаковыми стендом и фикстурой.
Исходный runtime загружается из указанной Git-ревизии через build-плагин Vite;
файлы рабочей копии не заменяются. Список модулей и SHA-256, хеши стенда и
фикстуры записываются в `dist/tree-builds.json`.
Сравнение ограничено перечисленными шестью runtime-модулями: остальные зависимости
общие. Для будущих сравнений с изменёнными зависимостями набор подмен нужно
пересмотреть; это не сборка произвольного старого состояния всего приложения.

Открыть по очереди:

- `http://localhost:5174/dist/tree-before/src/test/items-page-benchmark.html`.
- `http://localhost:5174/dist/tree-after/src/test/items-page-benchmark.html`.

Нажать «Замерить раскрытие дерева». Сохранить результаты до следующей сборки:
обычный `npm run build` удаляет тестовые пакеты из `dist`. В исходный HTML
приложения стенд не включён. Запись и удаление сохранённого каталога в стенде
отключены; отчёт проверяет неизменность исходного ключа localStorage.

## Методика и границы

- Пять сценариев: 100 и 1000 корней в реагентах; 1000 тех же корней в избранном;
  1000 корней с цепочкой глубиной 12; 1000 корней с широкой веткой из 40 материалов.
- Восемь соседних корней раскрыты заранее. У измеряемого корня раскрыта вся
  цепочка; состояние вложенных путей сохраняется при сворачивании корня.
- Три прогревочных переключения, затем 20 измерений: десять открытий и десять
  закрытий. Начальное появление списка исключено. Перед серией проходят
  анимации подготовленных ветвей.
- Последовательность синтетических Pointer Events + click включает путь
  кандидата переноса. Время события содержит синхронную работу React/DOM;
  отдельно записывается задержка до первого RAF-вызова и ещё 250 мс интервалов
  после него. Синтетический ввод не заменяет отдельную проверку реальных кликов.
- RAF оценивает доступность основного потока для кадров; он не измеряет
  непосредственно экранный FPS и не разделяет Layout/Paint/GPU. Это ограничение
  не позволяет объявлять достижение постоянных 60 FPS по одному числу.
- Production React не вызывает `Profiler.onRender`: `medianRenderMs` равен
  `null`, нулевые `renderMs` внутри сырых чтений означают отсутствие профилирования.
- Иконка встроена в data URL: ошибки заглушки и внешние запросы исключены.
  Предварительные dev-прогоны с неисправными иконками не используются в выводах.
- Оба пакета проверяются в одном профиле и одном десктопном окне. Поиск, цены,
  план, ввод и сохранение отдельно покрываются пользовательскими RTL-тестами.

## Результаты 18.10.2026

Chrome 155, Windows, встроенный браузер Codex, окно 886 × 967 CSS px.
Сводные значения округлены до 0,1 мс; квантили — nearest rank. Исходные агрегаты:
[до](tree-expansion-production-before.json), [после](tree-expansion-production-after.json).
[Манифест](tree-expansion-builds.json) содержит контрольные суммы исходников.

Медиана задержки до первого RAF-вызова при **открытии**, исходная → итоговая:

- 100 корней, реагенты: 120 → 25,5 мс.
- 1000 корней, реагенты: 1315,4 → 92,6 мс.
- 1000 тех же корней, избранное: 1372,2 → 93,5 мс.
- 1000 корней, 12 промежуточных уровней: 3428,1 → 150 мс.
- 1000 корней, 40 материалов в ветке: 3087,3 → 122 мс.

Для обычной ветки при 1000 корней p95 интервалов RAF во время открытия:
1395,8 → 90 мс. Синхронная часть открытия: медиана 392,3 → 4,4 мс;
после пакетирования часть работы выполняется в микрозадаче, поэтому именно
задержка первого кадра и интервалы RAF учитывают её, а время обработчика — нет.
Общая медиана всех переключений смешивает быстрое закрытие и более дорогое
открытие; выводы об открытии сделаны по отдельной группе из десяти измерений.

Улучшение заметное, но постоянные 60 FPS на списке из 1000 корней не достигнуты
в этом окружении: длинные кадры остаются. Память DOM и начальное монтирование
всех корней сохраняются; браузер пропускает дальнейшую отрисовку вне экрана.
Старые браузеры, не поддерживающие CSS containment, используют обычную раскладку.

Промежуточный эксперимент с Flex и `contain: layout` не улучшил открытие глубоких
веток и полностью отменён. Замеры с неисправными заглушками не входят в эти числа.
Маркер `opening` добавлен в отчёт после исходного прогона без изменения
последовательности ввода; исходные группы восстановлены из её чередования.

В production-пакете реальным вводом проверены мышь, Enter/Space, сохранение
раскрытия после поиска, Alt + стрелки, перенос мышью рядом с раскрытым деревом
и в конце прокрученного списка, фокус на последней строке и видимая за границей
корня подсказка прибыли. Все 100 строк проверочного каталога оставались в DOM,
`data-drag-layout` снимался после переноса. Ошибок консоли нет; сохранённый каталог
не изменился. Длинные названия проверены визуально в сценариях дерева.
