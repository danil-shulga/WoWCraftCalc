# Подписки TSM

- Клиент запускается в App независимо от настроек. Широкая подписка
  `useTsmStore()` допустима в открытом `TsmSettingsSection`, а не в App;
  статусы, ошибки и время проверки не должны перерисовывать всё приложение.
- Для цен используй `usePriceContext` с отдельными селекторами снимка и области.
  Новый снимок должен обновлять суммы при закрытых настройках. Не меняй
  расписание, отмену и проверку актуальности ответов ради оптимизации подписок.
- После удаления старого TSM-кэша из localStorage уведомляй индикатор объёма
  один раз на серию, включая удаления до частичного отказа. Запись и очистка
  sessionStorage не меняют объём localStorage и не требуют уведомления.

- TSM поддерживается в TBC и Classic Era; Forever использует ручные цены.
  `selectActivePricing` выбирает независимые `tbcPricing`/`classicPricing`.
  Общие UI-компоненты получают активную версию и не копируются для Classic.
- В ключах снимков и запросов учитывай версию. Рынок без `version` — прежний
  TBC; Classic требует `version: "classic"`. Не используй чужую версию источника.
- SessionStorage сохраняет максимум по одному выбранному рынку каждой версии,
  включая переход в Forever; снятие выбора очищает только рынок своей версии.
- Реестр `tsm-markets.json` общий для Python и клиента; объединённые миры
  представлены одним рынком с `aliases` для поиска. Сеть в тестах подменяется.

- CSV Era может не содержать `updatedAt` во всех строках: `scannedAt: null`
  допустим только для Classic. Не подставляй время загрузки или HTTP Last-Modified.
  Сохраняй проверку хэша и равенства дат manifest/снимка, включая `null`.
  Сравнивай давность только двух известных дат; UI явно сообщает о неизвестной
  свежести. Смешанные, повреждённые и будущие даты CSV отклоняй; TBC требует дату.
