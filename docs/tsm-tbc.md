# Цены TSM для TBC Anniversary

В настройках TBC выберите регион, игровой мир и фракцию. Приложение не назначает
рынок автоматически. Поддерживаются оба аукциона Thunderstrike и Spineshatter
в Европе; Dreamscythe, Nightslayer и Maladath (AU) в Северной Америке.
Список взят из официального реестра TSM, все десять CSV проверены 13.10.2026.
Maladath публикует старые снимки; наличие выгрузки не означает свежесть цен.

«Цена TSM для расчётов» едина для покупки и продажи:

- «Текущая оценка» (`recent` / DBRecent), по умолчанию;
- «Рыночная цена» (`marketValue` / DBMarket).

В редакторе есть отдельный флажок «Использовать цену TSM» для покупки и продажи.
Ручные суммы сохраняются, поля отключаются только пока выбран TSM. Отмена
отбрасывает черновик, сохранение применяет источники вместе с описанием и рецептом.
Сопоставление использует игровой ID из `source.wowheadItemId` своего workspace
TBC. Без ID цену TSM получить нельзя; поиск ID по названию не выполняется.

Нижний переключатель списка «Основные цены» соблюдает индивидуальные источники.
«Все по TSM» использует TSM для покупки и продажи всех предметов, включая
вложенные реагенты. Переключение не меняет источники или ручные суммы.
Массовое редактирование изменяет ручные суммы; рядом показывается используемая
цена TSM. «Авто / Купить / Крафтить» и сценарии профессий работают независимо.

Отсутствующий предмет, показатель или снимок означает неизвестную цену `null`.
Нет подстановки ручной суммы, другого показателя или нуля. Ручной `0` допустим.
В публичном CSV TSM нулевые значения нормализуются в `null`: при проверке
Thunderstrike Alliance у предмета 878 было `recent=0`, `minBuyout=0`,
`marketValue=173`; подобные строки встречаются во всех проверенных рынках.
Это соответствует отсутствию текущего аукционного значения, а не бесплатной
продаже. [TSM описывает ценовые источники как положительные суммы](https://support.tradeskillmaster.com/what-is-a-price-source).

## Клиент и сохранение

Клиент запрашивает `data/tsm/manifest.json` и только выбранный рынок с того же
статического сайта. Он проверяет схемы, рынок, дату и SHA-256 содержимого.
Показатель меняется локально; неизменный идентификатор содержимого исключает
повторную загрузку снимка. Проверки выполняются при запуске, переходе в TBC,
смене рынка, каждые 15 минут в открытой видимой вкладке и при возвращении,
если интервал прошёл. Кнопка получает опубликованные данные сайта.

Снимок помечается устаревшим после шести часов, но остаётся доступным для расчётов.
Показывается фактическое `scannedAt` TSM, отдельно от `generatedAt` manifest
и клиентского `loadedAt`. Ошибка сети сохраняет предыдущий успешный снимок
этого рынка. Смена рынка немедленно исключает прежние цены. Ответы проверяют
версию, `workspaceRevision`, рынок и актуальный запрос.

Настройки `tbcPricing` и индивидуальные источники входят в persistence v1
и полную резервную копию v1. Отсутствие новых полей совместимо с текущими
копиями: рынок не выбран, показатель `recent`, режим индивидуальный;
отсутствующий источник равнозначен `manual`. Адаптера старого одиночного
каталога нет. Внешний кэш хранится отдельно: `craftcalc-tsm-v1-tbc-<region>-<realm>-<faction>`;
он не экспортируется. Ошибка записи кэша показывается в настройках.

## Подготовка и GitHub Pages

Источник — [публичные CSV TSM](https://tradeskillmaster.com/public-data), без ключа:
`https://public-data.tradeskillmaster.com/classic/<region>-fresh/realm/<realm>-<faction>/items.csv`.
Обработчик `scripts/tsm/contract.py` строго проверяет семь колонок,
целые безопасные суммы, ID, дубли, единое время сканирования, повреждённые CSV
и пустую выгрузку. `src/domain/tsm-markets.json` — общий список для клиента
и обработчика. Новые рынки добавляются после проверки их официальных путей.

Python 3.12+ и Node.js из `package.json`:

```shell
npm run tsm:test
npm run build
npm run tsm:refresh
npm run preview
```

Команды создают локальную сборку со свежими снимками, ничего не публикуют.
`npm run dev` автоматически подготавливает снимки в `public/data/tsm` перед
запуском Vite. Эта папка исключена из Git. Если сервер уже работает, обновите
данные командой `npm run tsm:refresh:dev`, затем нажмите «Проверить обновление»
в настройках. При сбое TSM сохраняются предыдущие локальные снимки;
перезапуск dev-сервера обновляет их, но не запускает почасовое расписание Actions.
Каждый `npm run build` очищает `dist`, поэтому обновление выполняется после сборки.
Для сохранения опубликованных снимков при повторной подготовке:

```shell
python scripts/tsm/update.py --output dist/data/tsm --previous-url https://USER.github.io/CraftCalc
```

`update.py` сначала скачивает предыдущий manifest и все его снимки с Pages,
проверяет контрольные суммы и контракт. Ошибка восстановления прекращает
подготовку, чтобы новый deploy не удалил доступные цены. HTTP 404 manifest
означает первый запуск без опубликованных снимков. При сбое отдельного
рынка TSM или более старом ответе сохраняется его предыдущая успешная версия.
Первый запуск с недоступным TSM создаёт пустой manifest, приложение остаётся рабочим.

Workflow `.github/workflows/deploy.yml` запускается по push в main,
вручную и каждый час на 17-й минуте. Он собирает приложение, восстанавливает
предыдущие снимки и обновляет цены, затем загружает единый Pages-артефакт.
Генерируемые цены не коммитятся. Неизменные цены пропускают плановую публикацию;
push и ручной deploy публикуют код независимо от изменений цен.

Все запуски используют одну очередь `pages` без прерывания текущей публикации,
берут актуальный main и перед загрузкой артефакта сверяют его HEAD с remote.
Запуск с устаревшим кодом пропускает deploy. Последовательное восстановление
с опубликованного сайта исключает перезапись новых цен старой параллельной сборкой.

[Расписание Actions может задерживаться, а в публичном репозитории отключается
после 60 дней без активности](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
Клиент сообщает дату снимка, а не обещает точный час обновления.

Проверки обработчика моделируют первый запуск, неизменные данные, отказ TSM,
отказ восстановления и старый ответ. Настоящий deploy и конкурентные запуски
на GitHub требуют отдельной публикации; локальная проверка их не заменяет.
