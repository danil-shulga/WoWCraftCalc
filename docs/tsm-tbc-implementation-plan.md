## Согласованное поведение

### Область интеграции

- На первом этапе цены TSM доступны только в workspace `tbc` — TBC Anniversary.
- Сохранить статический SPA для GitHub Pages, без собственного сервера и БД.
- Интерфейс только для десктопа. Не добавлять адаптивные стили и проверки
  разных размеров экрана.
- Сохранить существующий список предметов и расположение его цен.
- Сохранить способы получения «Авто / Купить / Крафтить» и существующие
  сценарии расчёта. Новый источник цены не заменяет способ получения.

### Настройки пользователя

В существующий диалог настроек добавить блок «Цены аукциона · TSM» для TBC:

- регион;
- игровой мир с поиском по поддерживаемым мирам;
- фракция;
- единый выбор «Цена TSM для расчётов»: «Текущая оценка» или «Рыночная цена»;
- время снимка TSM, состояние загрузки и кнопка «Проверить обновление».

Выбранный показатель общий для покупки и продажи всех предметов. Не создавать
отдельные выборы показателя для покупки, продажи или каждого предмета.

- «Текущая оценка» соответствует `recent` / `DBRecent` и используется по умолчанию.
- «Рыночная цена» соответствует `marketValue` / `DBMarket`.
- Минимальный выкуп, исторические и региональные цены не включать в выбор.
- Мир пользователь выбирает самостоятельно; не назначать произвольный рынок.

### Редактирование предмета

Для цены покупки и цены продажи независимо добавить по одному чекбоксу
«Использовать цену TSM»:

- чекбокс выключен — используется сохранённая ручная сумма;
- чекбокс включён — используется выбранный в настройках показатель TSM;
- рядом с чекбоксом показываются сумма TSM и название показателя;
- ручная сумма всегда сохраняется, включая переключение на TSM и обратно;
- в согласованном макете ручные денежные поля отключены при включённом TSM;
- изменения источника применяются при сохранении; отмена сохраняет прежние данные.

Не добавлять отдельную радиокнопку или чекбокс «Ручная цена».

### Режим всего списка

Снизу слева страницы добавить переключатель:

- **Основные цены** — рассчитывать по ценам, заданным в каждом предмете:
  ручным или TSM, в зависимости от выбранного источника отдельно для покупки
  и продажи.
- **Все по TSM** — использовать выбранный показатель TSM для покупки и продажи
  всех предметов, включая вложенные реагенты.

Пользователь явно подтвердил, что «Все по TSM» относится и к покупке,
и к продаже всех предметов.

Глобальное переключение не меняет индивидуальные источники и ручные суммы.
После возврата к «Основным ценам» снова действуют сохранённые источники.

Обновление данных TSM не зависит от режима расчёта или чекбоксов предметов.
Режим и чекбоксы определяют использование цен, а не обновление снимка.

### Неизвестные цены и сопоставление

- Сопоставлять предмет с TSM по игровому ID из `source.wowheadItemId`,
  с проверкой принадлежности workspace TBC. Не сопоставлять по названию.
- Для предмета без игрового ID объяснять недоступность TSM в редакторе.
  Не расширять задачу автоматическим поиском ID по имени.
- Отсутствующий предмет или выбранный показатель означает неизвестную цену `null`.
- Не подставлять автоматически другой показатель, ручную сумму или ноль.
- Различать неизвестную цену и допустимую ручную цену `0`.
- Перед нормализацией проверить семантику нулевых значений именно в CSV TSM:
  значение отсутствия данных не должно превращаться в бесплатный предмет.
- Неизвестная цена распространяется на зависимые расчёты по текущим правилам.
- Быстрое и массовое редактирование сумм меняет ручные значения, сохраняя
  выбранные источники. Отображение используемой цены остаётся согласованным
  с источником и глобальным режимом.

описывают рынок и не гарантируют совершение сделки.

## Обновление и публикация снимков

Предлагаемый механизм:

1. GitHub Actions каждый час проверяет выгрузки поддерживаемых рынков TBC.
2. Обработчик проверяет CSV и создаёт JSON с обоими показателями.
3. Небольшой manifest содержит рынок, время снимка, ссылку и идентификатор
   содержимого JSON. Смена одного показателя не требует сетевого запроса.
4. Публиковать приложение и снимки единым артефактом GitHub Pages.
   Сгенерированные цены не коммитить в репозиторий.
5. Если данные не изменились, плановый запуск пропускает публикацию.
   Изменения кода при обычном deploy должны публиковаться независимо от цен.
6. При сбое отдельного рынка сохранять его предыдущий успешный снимок.
   Предусмотреть получение предыдущих снимков и при обычной сборке приложения,
   чтобы новый deploy не удалял доступные цены.
7. Согласовать конкурентные запуски обновления данных и публикации кода:
   старый запуск не должен перезаписывать новую публикацию.

В клиенте:

- загрузка manifest и выбранного рынка при запуске, смене рынка и переходе в TBC;
- проверка обновлений каждые 15 минут, пока приложение открыто;
- проверка при возвращении во вкладку, если интервал уже прошёл;
- кнопка «Проверить обновление» получает последний опубликованный снимок,
  но не запускает скан TSM или GitHub Actions;
- кэш последнего успешного снимка отдельно от каталога;
- ключ кэша включает версию игры, регион, мир и фракцию;
- состояние загрузки, отсутствие данных, ошибка сети и давность снимка различаются;
- смена рынка не должна показывать цены предыдущего рынка;
- результаты старых запросов не применяются после смены рынка, workspace
  или его поколения; учитывать существующий `workspaceRevision`;
- не сохранять производные расчёты и не смешивать время сканирования TSM,
  генерации JSON и клиентской загрузки.

Расписание GitHub Actions не гарантирует точное время запуска. Учитывать
возможные задержки и отключение расписания в публичных репозиториях после
60 дней отсутствия активности. Интерфейс сообщает фактическую дату снимка.

## Критерии готовности

- Выбор `recent` / `marketValue` меняет все расчёты, использующие TSM,
  для покупки и продажи, включая вложенные рецепты.
- «Основные цены» соблюдает индивидуальные источники.
- «Все по TSM» охватывает покупку и продажу всех предметов и не меняет
  индивидуальные источники либо ручные суммы.
- Переключение обратно восстанавливает расчёт по сохранённым источникам.
- Отмена редактора ничего не меняет; сохранение применяет оба источника корректно.
- Нет данных TSM — неизвестная цена, без скрытой подстановки.
- Обновление снимка пересчитывает затронутые предметы и всех родителей.
- Старые ответы и цены другого рынка не попадают в текущие расчёты.
- Выбор рынка, показателя и источников восстанавливается после перезагрузки
  и полного экспорта/импорта.
- Ручные суммы, другие версии игры и существующие сценарии работают как прежде.
- Приложение работает как статический сайт с `base: './'`, без API-ключа в браузере.
