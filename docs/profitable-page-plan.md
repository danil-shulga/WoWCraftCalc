# План реализации страницы «Выгодные»

Статус: реализовано 19.10.2026. Документ сохранён как исходный план; актуальные
формулы, поведение и ограничения описаны в [документации](profitable.md).
По последующему решению параметры и пороги убраны: комиссия фиксирована на 5%,
списки показывают все результаты. Описанные ниже параметры — исторический план.
Основание — пункт 3 в [TODO](../TODO.md) и согласованный интерактивный макет.

## 1. Согласованный объём

- Анализировать только предметы пользовательского каталога активной версии.
  Справочник не загружать и предметы автоматически не добавлять.
- Реализовать четыре режима: «Покупка», «Продажа», «Крафт и продажа», «Распыление».
- В шапке разместить кнопку «Параметры» вместо действий «Редактировать цены»
  и «Добавить». Она открывает встроенную панель, как в макете.
- Оставить поиск, сортировку, краткую строку применённых критериев, счётчик
  результатов и список с расчётами за один предмет.
- Использовать действующие оформление версии игры, язык названий и формат денег.
- В первой реализации строки показывают результаты без редактирования каталога.
  Дополнительные действия с планом, избранным и раскрытие дерева в макет не входят.
- Сохранить статическую архитектуру GitHub Pages и текущий клиент TSM.

## 2. Решения, предлагаемые для реализации

Эти детали уточняют макет и являются предложением плана, а не уже реализованным
поведением.

### Предметы каждого режима

- «Покупка» и «Продажа»: все добавленные предметы с подходящим игровым ID
  и двумя доступными показателями TSM своего рынка и версии.
- «Крафт и продажа»: добавленные предметы с эффективным рецептом, включая
  поддерживаемые преобразования эссенций. Раздел, в котором предмет добавлен,
  не ограничивает наличие рецепта.
- «Распыление»: добавленные предметы с отметкой `disenchanting`, как на существующей
  странице. Материалы берутся из того же каталога; отсутствие материала не приводит
  к автоматическому импорту.
- Строку идентифицировать внутренним `Item.id`. Предмет в нескольких разделах
  показывать один раз. Разные предметы с одинаковым игровым ID не объединять;
  неоднозначность материалов распыления обрабатывать существующим способом.

### Источники цен

- В «Покупке» и «Продаже» всегда сравнивать `recent` с `marketValue`, независимо
  от выбранного общего показателя для обычных расчётов. Применять `getTsmPrice`
  с двумя явно заданными показателями, сохраняя проверку версии и рынка.
- `marketValue` называть «Рыночная цена»: это существующий ориентир TSM,
  а не вычисленная приложением средняя за произвольный период.
- При отсутствии одного из показателей не подставлять ручную сумму: такое
  сравнение не должно смешивать разные источники.
- В крафте и распылении использовать обычный `PriceContext`, приоритетные цены
  и действующую подстановку ручной цены/TSM. Реагенты и материалы разрешать через
  существующий `resolveItemPrice`.
- Для этих двух режимов переиспользовать `PriceModeSelector`. Показывать фактический
  источник суммы; выбранный `marketValue` не подписывать «Текущая оценка».
- «Текущая оценка» не означает минимальный выкуп доступного лота. Загрузку
  `minBuyout`, историю цен и новые сетевые источники в эту задачу не включать.

### Параметры

- Для покупки: минимальное отклонение вниз от рыночной цены, минимальная
  потенциальная прибыль, комиссия продажи.
- Для продажи: минимальное отклонение вверх от рыночной цены и комиссия.
  Минимальную прибыль не показывать, поскольку стоимость приобретения неизвестна.
- Для крафта: минимальная доходность, минимальная прибыль, комиссия,
  флажок «Только выбранные профессии».
- Для распыления: минимальная доходность, минимальная ожидаемая прибыль, комиссия.
  Первый вариант считает покупку предмета → распыление → продажу материалов,
  как в макете. Выбор крафта исходного предмета — отдельное последующее расширение.
- Предложенные начальные значения из макета: 15%, 1 золотой, комиссия 5%,
  только выбранные профессии. Комиссия — редактируемое допущение пользователя,
  а не автоматическое определение аукциона по миру.
- Параметры хранить отдельно для четырёх режимов и каждой версии игры.
  Последний режим, поиск и сортировку оставить состоянием интерфейса.
- Настройки сохранять только по «Применить». Ввод не меняет результаты и каталог.
  «Отмена» отбрасывает черновик выбранного режима.
- При переключении режима сохранять несохранённые черновики в памяти страницы;
  при возврате показывать их снова. Скрытые панели исключать из взаимодействия
  через `hidden`/`inert`, черновики регистрировать в `draft-guard.ts`.
- Для ухода со страницы следовать действующему поведению приложения; защиту
  переключения версии проверить через общий механизм. Новую общую систему
  блокировки навигации в рамках этой задачи не вводить.

## 3. Контракт расчёта

Все формулы находятся в `src/domain`. Обозначения: `R` — `recent`, `M` —
`marketValue`, `f` — комиссия в долях единицы, `C` — затраты, `S` — цена продажи,
`V` — точная ожидаемая стоимость материалов распыления.

### Покупка

- Отклонение вниз: `(M − R) / M × 100`.
- Ожидаемая выручка при продаже по рыночной цене: `M × (1 − f)`.
- Потенциальная прибыль: `M × (1 − f) − R`.
- Колонки: предмет, текущая оценка, рыночная цена, потенциальная прибыль,
  «Ниже рынка, %».
- В выдачу попадает только положительное отклонение с положительной прибылью,
  удовлетворяющее включительным порогам. Дисконт меньше комиссии может оказаться
  невыгодным, даже если исходное отклонение достаточно велико.

### Продажа

- Превышение рынка: `(R − M) / M × 100`.
- Выручка после комиссии: `R × (1 − f)`.
- Колонки: предмет, рыночная цена, текущая оценка, выручка после комиссии,
  «Выше рынка, %».
- В выдачу попадает положительное превышение, удовлетворяющее порогу.
  Выручку и превышение цены не называть прибылью.
- Основная сортировка — по выручке; альтернативная — по превышению рынка.

### Крафт и продажа

- `C` получать через `getExactCraftUnitCost` с учётом выхода рецепта,
  вложенных рецептов, методов получения и сценария профессий.
- Чистая прибыль за единицу: `S × (1 − f) − C`.
- Доходность затрат: `прибыль / C × 100`.
- Флажок профессий ограничивает доступность корневого рецепта. Преобразования
  эссенций и рецепты без указанной профессии не требовать привязывать к профессии.
- При включённом флажке вложенные расчёты используют текущие профессии и сценарий
  `configured`. При выключенном — существующий `all-professions`; его семантику
  не менять. Явные методы получения трактовать по правилам соответствующего сценария.
- Колонки: предмет, себестоимость, продажа до комиссии, прибыль после комиссии,
  доходность. Не использовать готовую прибыль за крафт как прибыль за единицу.

### Распыление

- Правила, вероятности, запреты и сопоставление материалов переиспользовать из
  `disenchanting.ts` и `disenchanting-catalog.ts`.
- `C` — используемая цена покупки предмета. `V` брать из
  `exactExpectedValueCopper`, не из округлённой суммы.
- Ожидаемая прибыль: `V × (1 − f) − C`.
- Доходность: `ожидаемая прибыль / C × 100`.
- Колонки: предмет, покупка, ожидаемая стоимость материалов до комиссии,
  ожидаемая прибыль после комиссии, доходность.
- Сохранять существующее явное допущение равномерного количества
  `acceptUniformQuantities: true` и информацию о нём в деталях оценки.
- Комиссию применять один раз к продаже материалов; к стоимости покупки её
  не добавлять. Частично известную стоимость не считать полным результатом.

### Точность, пороги и неизвестные значения

- Цены и минимальную прибыль хранить в медных монетах; денежные пороги —
  неотрицательные безопасные целые. Для ввода использовать `MoneyInput`.
- Проценты — конечные неотрицательные числа; комиссию ограничить диапазоном
  0–100%. Валидация выполняется также в схеме и действии store.
- Точные себестоимость и математическое ожидание сохранять до вычисления
  окончательной суммы. Деньги округлять для отображения, фильтрацию и сортировку
  выполнять по неокруглённым результатам. Проверить границу округления отдельным тестом.
- Порог применять через `>=`; при этом первая версия показывает только
  положительные возможности. Нулевые и отрицательные результаты не включать.
- `null` означает неизвестность, `0` остаётся известной суммой. При нулевых
  затратах не делить на ноль: прибыль известна, доходность неизвестна. При активном
  положительном пороге доходности строка не проходит; при нулевом пороге допускается
  по денежному критерию с подписью «Не определена» в колонке процентов.
- Проверять конечность и безопасный диапазон денежных результатов. Не выводить
  `NaN`, `Infinity` и неверные суммы как выгодные предложения.
- Комиссия действует только внутри «Выгодных». Формулы каталога, распыления
  на его собственной странице и планировщика сохраняют существующий смысл.

## 5. Поведение страницы

### Поиск, сортировка и пересчёт

- Нормализованные имена RU/EN готовить при изменении каталога, запрос — при
  изменении ввода. Поиск работает по обоим языкам.
- Сначала вычислять снимок текущего режима, затем фильтровать и сортировать
  готовые строки. Минимальные пороги не участвуют в обходе рецептов.
- Себестоимость зависит от каталога, версии, цен и сценария профессий.
  Изменение комиссии пересчитывает только выручку, прибыль и доходность.
- Поиск, язык, порядок отображения, открытие панели, ввод черновика и фоновые
  статусы TSM не должны повторять расчёт графа рецептов или распыления.
- Кэшировать результат текущего набора входов через `useMemo`; не строить
  постоянный архив всех комбинаций параметров и сценариев.
- Новый снимок TSM должен обновлять суммы и при закрытых настройках. Использовать
  `usePriceContext`, не широкую подписку `useTsmStore()` в App.
- При равенстве числовых значений сортировать по отображаемому имени, затем ID.
  Неизвестный процент располагать после известных при сортировке по доходности.
- Счётчик показывает «Подходит: N из K», где K — число кандидатов текущего
  режима до поиска и порогов. Недоступные расчёты учитывать отдельно с причиной.

### Пустые состояния и статус данных

- Различать пустой каталог, отсутствие кандидатов текущего режима, отсутствие
  подходящих результатов и невозможность оценки из-за данных.
- При неизвестной оценке дать краткое раскрываемое объяснение и причины по предметам;
  не предлагать автоматически добавлять материалы.
- Рынок и свежесть показывать компактно. Известную дату брать только из
  `scannedAt`; для Classic с `null` явно сообщать «Время снимка неизвестно».
- Сетевой сбой с сохранённым снимком своего рынка не очищает результаты.
  Без снимка крафт/распыление могут работать по ручным ценам, сравнение рынка — нет.
- В Forever «Покупка» и «Продажа» недоступны из-за отсутствия TSM,
  «Распыление» — из-за отсутствия подтверждённого набора. «Крафт и продажа»
  работает по ручным ценам. Недоступность режима сопровождается пояснением.
- Долгую давность снимка показывать по существующему правилу TSM, без отдельного
  нового таймера или дополнительного механизма обновления.

### Доступность и анимации

- У кнопки «Параметры» — `aria-expanded`/`aria-controls`, у полей — видимые
  подписи. Ошибки связаны с полями; отмена и применение возвращают фокус на кнопку.
- Escape закрывает открытую панель, сохраняя несохранённый черновик до отмены,
  применения или ухода со страницы. Панель не является модальным диалогом и не
  захватывает фокус. Скрытые панели недоступны для клавиатуры.
- При изменении состава списка использовать общую разметку строки и принятый
  подход PlannerPage/RecipeEditor: grid 0fr ↔ 1fr и прозрачность, 150 мс, ease-out.
- Уходящая строка хранит последние данные, стабильный ключ, `inert` и
  `aria-hidden`; удаляется по своему `animationend`. Последняя строка не должна
  исчезать вместе с оболочкой до завершения анимации.
- Быстрое возвращение предмета в результаты отменяет уход без дубликата.
  Изменение сумм или сортировки не запускает повторное появление той же строки.
- При reduced motion использовать 1 мс там, где завершение зависит от события.
  Переключение целого режима показывать как смену набора, без сохранения строк
  предыдущего режима под заголовками нового.

## 6. Последовательность небольших шагов

### Шаг 1. Типы и схемы параметров

Создать `profitability-settings.ts` и ближайшие тесты: режимы, начальные значения,
денежные пороги, проценты, некорректные входы. Параметры не должны попадать в Item.

Проверка: профильный Vitest; критерий готовности — явный контракт всех четырёх
режимов, включая отсутствие денежного порога в продаже.

## 7. Обязательные сценарии приёмки

- Каталог содержит один предмет в нескольких разделах: в выдаче нет дублей.
- В покупке есть дисконт, но после комиссии убыток: предмет не предлагается.
- В продаже неизвестна цена приобретения: показывается выручка, без прибыли.
- Рецепт выдаёт несколько предметов и использует вложенный дробный выход:
  прибыль считается за единицу без преждевременного округления.
- Профессия корневого рецепта не выбрана: поведение соответствует флажку;
  встроенное преобразование эссенций не блокируется этим флажком.
- У материала распыления отсутствует цена, сам материал или однозначный ID:
  полной оценки нет, причина доступна, каталог не меняется.
- Ручной ноль не заменяется TSM, неизвестная цена не становится нулём.
- Граница порога проверяется по точному значению; округление отображения
  не меняет решение фильтра.
- Изменение комиссии не запускает обход рецептов/правил распыления повторно.
- Новый снимок своего рынка меняет результаты при закрытых настройках;
  старый снимок чужого рынка/версии не используется.
- Classic с неизвестной датой не получает фиктивную свежесть.
- Применение, отмена, Escape, переход между режимами, смена версии и импорт
  backup корректно обрабатывают параметры и черновики.
- Последняя строка, массовое исчезновение, быстрое возвращение и reduced motion
  завершаются без зависших или дублированных строк.
- Браузерная проверка выполняется только на `http://localhost:5174/`, на одном
  десктопном размере, с длинными названиями и сохранением тестовых данных.
  Работающий сервер переиспользуется; порт 5173 не затрагивается.

## 8. Граница первой реализации

Не входят: сканирование всего справочника, минимальный выкуп реальных лотов,
история и графики, оценка спроса, депозиты и повторные выставления, наличие вещей
в сумках, автоматические сделки, новые действия планировщика и оптимизация
изготовления целых партий. Потенциальная прибыль от перепродажи и математическое
ожидание распыления остаются оценками по доступным данным.
