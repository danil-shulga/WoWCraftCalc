# План: добавление нескольких предметов из базы

Статус: реализовано 17.10.2026. Основание — пункт 4 в [TODO](../TODO.md).
План ниже учитывает уточнения пользователя: выбор повторным кликом без флажков,
новые выбранные позиции сверху и отсутствие автопрокрутки окна вниз.

Цель: в одном окне выбрать несколько предметов из базы активной версии,
проверить рецепт и выход каждого, затем добавить весь набор одним подтверждением.

## Границы и поведение

- Массовый выбор доступен при добавлении в «Крафты», «Реагенты» и «Распыление».
  Редактирование существующего предмета через `targetItem` остаётся одиночным.
  Ручное добавление и импорт по ссылке Wowhead сохраняют текущий сценарий.
- Поиск RU/EN, фильтр профессии и страницы по 50 результатов сохраняются.
  Выбранные позиции не теряются при поиске, смене фильтра или страницы.
- У каждого выбранного предмета свой рецепт и выход. В наборе может быть только
  одна позиция на ID предмета базы; повторный выбор не создаёт дубль.
- В «Крафтах» рецепт обязателен. В остальных разделах можно выбрать импорт
  рецепта или только предмета. Начальный рецепт выбирается по текущей профессии,
  затем первый доступный — как в существующей форме.
- Начальный выход берётся из сохранённого рецепта, затем из базы, затем равен 1.
  `baseQuantityCandidate` не используется как подтверждённый выход.
  При смене альтернативы применяется нынешнее правило инициализации выхода;
  переключение между позициями сохраняет уже введённое значение каждой.
- До подтверждения каталог не меняется. Отмена закрывает окно и отбрасывает
  весь набор. После успешного импорта окно закрывается с возвратом фокуса,
  появляется одно итоговое уведомление.
- Ошибка любой позиции отклоняет весь набор; форма сохраняет выбор и значения,
  показывает предмет и причину ошибки, позволяет исправить набор и повторить.
  Пустой набор нельзя подтвердить.

## Что уже есть

- [ReferenceBrowser](../src/features/reference-database/ReferenceBrowser.tsx)
  хранит один `selectedId` и один `recipeId`, регистрирует выбор через `useDraftGuard`.
- [ReferenceReview](../src/features/reference-database/ReferenceReview.tsx)
  хранит выход, показывает состав и предупреждение о замене рецепта;
  подтверждение сразу вызывает действие store и закрывает форму.
- [Преобразование базы](../src/domain/reference-database-import.ts) уже проверяет
  подтверждённый выход и принадлежность рецепта базе, переносит метаданные.
- [useCraftStore](../src/store/useCraftStore.ts) предоставляет одиночные
  `importRecipe` и `addReferenceItem`. Каждое действие самостоятельно пишет каталог,
  поэтому цикл вызовов из UI не обеспечивает атомарность набора.
- [ItemsPage](../src/pages/ItemsPage.tsx) передаёт действия через
  [ItemAddModal](../src/features/item-editor/ItemAddModal.tsx) и
  [ItemSourceForm](../src/features/item-editor/ItemSourceForm.tsx).
  Защита версии и поколения workspace уже существует через `WorkspaceRequest`.

## 1. Подготовка набора и атомарное действие store

Файлы: `src/domain/recipe-import.types.ts`, `src/domain/reference-database-import.ts`,
`src/store/useCraftStore.ts`; при необходимости небольшой соседний модуль store
для общей подготовки каталога. Названия новых типов и файлов уточнить перед правкой.

1. Описать позицию пакета как различимый тип: отдельный предмет или рецепт.
   Передавать в store уже преобразованные данные, раздел и `WorkspaceRequest`.
   Результат действия: успех с итоговыми счётчиками либо ошибка с идентификатором
   проблемной позиции. Типы данных относятся к domain, результат действия — к store.
2. Выделить из одиночных действий только необходимую общую подготовку изменений
   без записи. Сохранить их внешние контракты, целевой импорт редактора,
   валидацию, сопоставление и обработку ошибок; не создавать временный Zustand-store.
3. Добавить действие `importReferenceBatch`: проверить запрос workspace,
   непустой набор, версии источников, профессии, данные и уникальность выбранных
   продуктов. Повтор одной выбранной позиции отклоняется; повтор реагента
   в разных рецептах допустим и должен разрешаться в один предмет каталога.
4. Сначала сопоставить все выбранные предметы и их непосредственные реагенты
   с каталогом и друг с другом, затем применить выбранные рецепты к общей копии.
   Сохранить проверки неоднозначности по источнику и названиям; конфликт двух
   разных выбранных продуктов, разрешившихся в один ID каталога, отклонять.
5. Проверить итоговый граф через существующую проверку каталога. Не отклонять
   допустимый итог только из-за промежуточного графа при замене нескольких рецептов.
   При любой ошибке не вызывать запись; при успехе обновить workspace одним `set`.
6. Сохранить ручные цены, источники цен, избранное, видимость, метаданные,
   вложенные рецепты и способы получения по правилам одиночного импорта.
   Явно выбранный рецепт заменяет активный; вариант «только предмет» сохраняет его.
   Если выбранный продукт одновременно является реагентом другой позиции,
   его выбранный рецепт и разделы не должны зависеть от порядка набора.
7. Считать созданные и переиспользованные предметы по уникальным итоговым ID,
   включая реагенты; число выбранных позиций и сохранённых рецептов считать отдельно.
   Не суммировать счётчики одиночных вызовов с повторяющимися реагентами.

Проверки: расширить `src/store/reference-database-import.test.ts` и ближайшие
domain-тесты. Покрыть смешанный пакет, общие реагенты, продукт в роли реагента,
повторный импорт, оба порядка связанных позиций, замену нескольких рецептов,
цикл только после объединения, неоднозначное сопоставление, неверную последнюю
позицию и устаревший `WorkspaceRequest`. При отказе сравнивать состояние и
localStorage с исходными; при успехе проверять одно уведомление подписчиков
и одну запись persistence. Повторно выполнить тесты одиночного и целевого импорта.

## 2. Управляемый предпросмотр без потери одиночного сценария

Файлы: `ReferenceReview.tsx`, `ReferenceBrowser.tsx`,
`reference-database-form.types.ts` в `src/features/reference-database`.

1. Вынести изменяемые значения выбранной позиции из внутреннего состояния
   предпросмотра в владельца черновика: ID предмета, ID рецепта или отсутствие
   рецепта, выход. Отдельно хранить ID открытого предпросмотра.
2. Переиспользовать общую разметку состава, поля выхода, предупреждения о замене
   и ошибок. Передавать значение и действие через props; не копировать JSX
   предпросмотра для одиночного и массового режимов.
3. В одиночном режиме оставить нынешнее подтверждение целевого импорта.
   В массовом режиме редактирование предпросмотра меняет только локальную позицию;
   общая кнопка подтверждения принадлежит форме набора.

Проверки: профильные тесты формы и `ItemEditModal.test.tsx`: выбор альтернативы,
выход из каталога, отсутствие рецепта, дробный/нулевой/небезопасный выход,
предупреждение о замене и атомарное сохранение описания с рецептом.

## 3. Выбор нескольких позиций и подключение к странице

Файлы: `ReferenceBrowser.tsx`, `ReferenceDatabaseForm.css`, при необходимости
компонент списка выбранных позиций рядом; `ItemSourceForm.tsx`, `ItemAddModal.tsx`,
`ItemsPage.tsx` и затронутые контракты/тестовые вызовы.

1. По уточнению пользователя выбирать предмет кликом по результату, без отдельного
   флажка: первый клик добавляет в набор и открывает предпросмотр, второй удаляет
   из набора. Использовать общие `Button`, `ItemIdentity` и `aria-pressed`.
   Для переключения предпросмотра выбранной позиции использовать её название
   в списке выбранных, сохраняя состав набора. Не прокручивать окно вниз
   при выборе или смене предпросмотра.
2. Показать компактный список выбранных предметов: новые позиции сверху, счётчик,
   открытие предпросмотра, удаление позиции и «Очистить выбор».
   При удалении открытой позиции открывать следующую, затем предыдущую;
   при пустом наборе скрывать предпросмотр. Сохранять понятное положение фокуса.
3. Настройки позиции сохранять при переключении предпросмотра и поисковых фильтров.
   Удаление убирает её из рабочего набора сразу; быстрое повторное добавление
   до конца анимации возвращает ту же позицию и значения без дубля.
4. Переиспользовать подход существующих списков `PlannerPage`/`RecipeEditor`:
   общая строка списка, grid-высота и opacity за 150 мс, отдельные уходящие строки
   с `inert`/`aria-hidden`, удаление по собственному `animationend`.
   Сохранять оболочку при очистке и удалении последней строки;
   при reduced motion сокращать длительность до 1 мс.
5. Зарегистрировать непустой набор через существующий `useDraftGuard`.
   При переключении вкладок источника сохранять черновик и `hidden`/`inert`.
   Смена версии с подтверждённой потерей черновика сбрасывает набор;
   старый запрос не должен применяться к новому workspace.
6. Передать новое действие от `ItemsPage` до формы добавления. Возможность
   массового выбора задавать явным контрактом, чтобы редактор с `targetItem`
   не получил её случайно. Найти все использования изменённых props и фикстуры.
7. По «Добавить выбранные (N)» преобразовать весь набор существующими domain-функциями,
   вызвать одно действие store и обработать результат. Ошибку привязать к позиции;
   при отказе не закрывать окно. Сохранить существующее сообщение об ошибках
   persistence: не показывать успешное сохранение при отказе localStorage.

Проверки через React Testing Library: выбор на разных страницах и по разным
запросам; независимые рецепты и выходы; снятие выбора, очистка, последняя строка,
быстрое повторное добавление, событие анимации потомка; отмена без изменений;
повтор после ошибки; сохранение вкладок; клавиатура, портальный выбор рецепта
